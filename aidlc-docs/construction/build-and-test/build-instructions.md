# Build Instructions

**Project**: TTO Test Analyst Agent System (TAAS)
**Phase**: CONSTRUCTION | **Stage**: Build and Test
**Version**: 1.0 | **Date**: 2026-08-31

---

## What "build" means here

TAAS has **two deliverables with different build stories**, and conflating them is the
first mistake to avoid.

| Deliverable | Built by | Runs where |
|---|---|---|
| `tto-testgen` — the Python MCP toolchain | `uv sync` | The operator's workstation, inside VS Code |
| The generated Playwright project | `npm ci`, by the operator | A Jenkins agent |

**This document covers the first.** The second is generated by U5, verified by U6, and
built by whoever runs `npm ci` after the handover — see `handover-manifest.md` in the
generated project.

There is no compilation step. "Build" means resolving a locked dependency set and
confirming the package imports.

## Prerequisites

| Requirement | Version | Why |
|---|---|---|
| Python | **3.11 or later** | `requires-python = ">=3.11"` |
| `uv` | 0.5 or later | The lockfile is `uv.lock`; `pip` will not honour it |
| SQLite | 3.35+ recommended | Below 3.35, `ALTER TABLE ... DROP COLUMN` is unavailable — migrations work around it, and the rehearsal in `docs/restore-procedure.md` assumes it |
| Disk | ~500 MB | The virtual environment and the corpus database |
| Node.js | **Not required** | Only for verifying a generated project; U6 reports `skipped` without it |

**No network access is needed after `uv sync`.** The toolchain reaches Atlassian and
Bitbucket only through MCP servers the operator configures.

## Build Steps

### 1. Install dependencies

```bash
uv sync --extra dev
```

**`--extra dev` is not optional for a build you intend to test.** Without it the
package installs but pytest, Hypothesis, import-linter and pip-audit do not, and the
first symptom is `ModuleNotFoundError: No module named 'tto_testgen'` from a test run —
which reads like a packaging fault and is not one.

### 2. Configure the environment

```bash
cp .env.example .env
```

Then set the two required variables. The build does not read them; `composition.build()`
does, and it fails naming **every** missing variable at once rather than the first.

| Variable | Purpose |
|---|---|
| `TAAS_ATLASSIAN_MCP_SCRIPT` | Path to `tt-atlassian-mcp`'s `atlassian_mcp_server.py` on this machine |
| `TAAS_BITBUCKET_MCP_SCRIPT` | Path to `tt-bitbucket-mcp`'s `bitbucket_mcp_server.py` on this machine |

**Neither is a credential.** TAAS spawns both scripts itself for bulk ingestion
(U2-01), but authenticates neither: `tt-bitbucket-mcp` reads git clones already on
disk and never contacts Bitbucket at all, and `tt-atlassian-mcp` authenticates from
its own `.env` file next to its script, which TAAS never reads. Set that server's
own `.env` up once, following its own README, before pointing
`TAAS_ATLASSIAN_MCP_SCRIPT` at it.

Everything else has a default. `.env.example` documents all of them.

**`--env-file` matters here.** `config.load()` reads only the process environment —
it does not parse `.env` itself — so `.vscode/mcp.json` launches the toolchain with
`uv run --env-file .env`, which is what makes `cp .env.example .env` actually take
effect.

### 3. Verify the build

```bash
uv run python -c "import tto_testgen; print('ok')"
uv run tto-testgen-mcp --help 2>/dev/null || echo "entry point registered"
```

**Expected output**: `ok`. There are no build artefacts to inspect — the package is
installed editable into `.venv`.

### 4. Verify the architecture holds

```bash
uv run lint-imports
```

**Expected**: `Contracts: 5 kept, 0 broken.`

This is part of the build, not of testing. The five contracts are what keep the domain
pure, the services free of concrete adapters, and `subprocess` confined to one module —
and a violation is a structural fault that should stop a build rather than surface in
review.

## Troubleshooting

### `ModuleNotFoundError: No module named 'tto_testgen'`

**Cause**: `uv sync` without `--extra dev`, which reinstalls the environment without
the editable project install the tests import.

**Fix**: `uv sync --extra dev`.

### `No solution found when resolving dependencies`

**Cause**: an exact pin conflicting with a transitive constraint — most often
`pydantic`, which `mcp` bounds from below.

**Fix**: relax the conflicting pin to a range, run `uv sync` to see what the resolver
chooses, then **pin that exact version back**. Leaving the range in place would
reintroduce the drift the pins exist to prevent.

### `lint-imports` reports a broken contract

**Cause**: a module acquired an import its ring forbids — most commonly a service
importing a concrete adapter, or a new module importing `subprocess`.

**Fix**: read the contract's own comment in `.importlinter`. Each states why it exists;
none is arbitrary, and the answer is always to move the dependency behind a port rather
than to relax the contract.

### `sqlite3.OperationalError: near "DROP": syntax error` during a migration rollback

**Cause**: SQLite older than 3.35.

**Fix**: none needed — the reverse migrations rebuild tables explicitly rather than
using `DROP COLUMN`, precisely so a rollback does not fail on an older build. If you see
this, a migration was written without its rebuild; check `verify_reversibility`.
